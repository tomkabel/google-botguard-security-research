## Remediation Plan (Ordered by Priority)

### Phase 1: Structural Restructuring (Critical Path)

#### Task 1.1: Redefine Scope & Threat Model for VLM (Sec 1.2, 1.3)
- **File:** `paper.md`, lines 50–70 (Scope paragraph) + lines 72–116 (Threat Model)
- **Problem:** Scope says attacker "controls the browser, the JavaScript runtime, the DOM, and every API the defense calls." VLM via OS accessibility layer controls none of these.
- **Fix:**
  - Update Sec 1.2 scope paragraph to: *"the attacker controls the browser environment, JavaScript runtime, DOM, and browser APIs — or, in the case of agentic AI systems, the OS-level input layer (mouse, keyboard, accessibility APIs) driving a legitimate unmodified browser."*
  - Add VLM/Agentic AI as a **third axis** in the dual-axis threat model (Sec 1.3):
    - Axis C — Attack Vector: Environmental Forgery (traditional instrumented browser) vs Operator Synthesis (VLM driving stock browser via OS layer)
  - Explicitly state VLM as the **new baseline threat model**, not a future concern
- **Verification:** No contradiction between scope definition and VLM treatment.

#### Task 1.2: Move VLM from Section 8.5 to Central Position
- **File:** `paper.md`, Section 1 (new subsection) + Sections 4.1–4.5 (architectures evaluated against VLM)
- **Problem:** VLM paradigm buried in "Open Problems" when it structurally invalidates most probabilistic defenses.
- **Fix:**
  - After Sec 1.3, add **Sec 1.4: The VLM/Agentic AI Paradigm Shift as the New Baseline** — 1–2 paragraphs summarizing: what VLMs are, how they drive browsers, shift from environmental forgery to operator synthesis
  - Add **VLM Resilience Assessment** paragraph to each architecture evaluation in Sec 4, explicitly assessing vulnerability to VLM-based attack
  - Fold Sec 8.5 content into body. Sec 8.5 becomes a pointer + forward-looking research on VLM-resilient attestation primitives
- **Verification:** Reader who reads only Sections 1–4 understands VLM paradigm shift.

#### Task 1.3: Restructure L1 to Separate Environmental Introspection from Behavioral Biometrics
- **File:** `paper.md`, Sections 5.2 (L1) and 4.3 (Behavioral Biometrics)
- **Problem:** Forcing behavioral biometrics into L1 creates category error. L1 is "detecting forged properties." Behavioral biometrics detect synthetic interaction patterns. VLM generates OS-native input.
- **Fix:**
  - Restructure Sec 5.2 into three sub-layers:
    - **L1a — Static Environmental Introspection:** navigator, WebGL, canvas, DOM consistency. Cost: profile virtualization.
    - **L1b — Dynamic Sensor Telemetry (Behavioral Biometrics):** mouse kinematics, scroll, touch, accelerometer. Cost: ML inference OR human labor.
    - **L1c — Operator Synthesis (VLM/Agentic AI):** VLM-generated OS-native input. **Cost: VLM inference + GPU compute.** Explicitly note this path does not forge L1a OR L1b — it satisfies them natively.
  - Add boundary condition to formulas: *"When attacker uses VLM agentic AI at OS layer, L1a and L1b detection are structurally bypassed."*
- **Verification:** Three sub-layers provide clear cost models for each attack vector.

### Phase 2: Economic Model Rigor

#### Task 2.1: Fix the Minimization Function (Sec 6.2 and 4.3)
- **File:** `paper.md`, Sec 4.3 (lines ~380–400), Sec 6.2 (lines ~470–490)
- **Problem:** `Cost_Bypass = min(Cost_ML_Inference, Cost_Human_Labor)` ignores CapEx, supply elasticity, latency, capacity constraint.
- **Fix:**
  - Expand to multi-constraint model:
    ```
    Cost_Bypass = min(
      Cost_ML_Inference + amortized_CapEx_per_token,
      Cost_Human_Labor_per_token,
      Cost_VLM_Inference_per_action
    )
    subject to:
      throughput ≤ min(ML_throughput, human_labor_supply, VLM_throughput)
      latency ≤ max_acceptable_latency
    ```
  - Add prose: supply elasticity (human labor inelastic at short timescales), latency (human labor: minutes/hours vs ML/VLM: sub-second), capacity ceiling (global click-farm workforce ~10^5–10^6), CapEx amortization
  - Explicitly state simple `min()` applies only under infinite supply / zero latency assumption
- **Verification:** Every economic expression includes domain of validity and constraints.

#### Task 2.2: Add VLM Boundary to Conjunctive Cost Model (Sec 4.2, 6.5)
- **File:** `paper.md`, Sec 4.2 (lines ~350–370), Sec 6.5 (lines ~530–550)
- **Problem:** `Cost_proxy + Cost_profile + Cost_license` assumes instrumented browser. VLM in stock browser eliminates profile and license.
- **Fix:**
  - Add: *"This conjunctive model applies when the attacker must subvert the browser environment. In the VLM paradigm (Section 1.4), the attacker uses a stock legitimate browser — eliminating Cost_profile and Cost_software_license. Attacker cost reduces to Cost_proxy + Cost_VLM_inference."*
- **Verification:** Conjunctive cost model includes boundary conditions.

#### Task 2.3: Add Black-Box Execution to L2 Temporal Model (Sec 5.7, 6.1)
- **File:** `paper.md`, Sec 5.7 (lines ~460–480), Sec 6.1
- **Problem:** L2 temporal model assumes attacker must RE the VM. VLM in stock browser skips RE entirely.
- **Fix:**
  - Add: *"When attacker executes VM in stock browser without instrumentation (VLM paradigm), RE requirement vanishes. T_RE > T_Life is replaced by: VM must execute without server-side heuristic detection. L2 provides zero marginal protection."*
  - Update Sec 5.7 to include this as explicit boundary condition
- **Verification:** Temporal arms race analysis explicitly acknowledges when it does not apply.

#### Task 2.4: Add Server-Side Cost Caveat (Sec 1.2 and Sec 6)
- **File:** `paper.md`, Sec 1.2 (Scope) and Sec 6 opening
- **Fix:**
  - End of Sec 1.2 scope: *"The economic analysis covers only client-side attack costs. Server-side defenses (WAF, TLS fingerprinting, rate limiting) impose additional orthogonal costs not modeled here."*
  - Sec 6 opening: add similar brief paragraph scoping the analysis
- **Verification:** All economic claims about "ceilings" explicitly scoped to client-side.
